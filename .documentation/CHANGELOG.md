# Changelog - Higgs Boson Firefox Theme

All notable changes to this project will be documented in this file.

## Format
- Each feature change should be added as a single unordered list item
- Format: `- **YYYY-MM-DD HH:MM** [Component] Brief description of change`
- Date and time should be bold (surrounded by double asterisks)
- Most recent changes at the top

## Changes

- **2026-10-19 20:15** [Animations] **render.js-inspired motion.** New `CSS/chrome/animations.css` + `JS/uiAnimations.uc.js`: a shared motion token pair (`--uc-motion-speed`/`--uc-motion-ease`), a radial **fan reveal** for the tab-group editor's colour swatches (arc maths ported from render.js's `layoutFan`, active swatch anchored, hovered swatch pops), coloured glow, and ambient hover micro-interactions. Prefs `userchrome.animations.{enabled,tabGroupFan,speed}`; honours `prefers-reduced-motion`. Docs: README feature, `preferences.md` + `css-variables.md` sections.

- **2026-10-19 19:45** [Docs/Prefs] **Renamed the custom pref namespace `higgs.*` → `userchrome.*`** across all scripts (`homeRedirect`, `workspaces`, `libraryRedirect`, `quick_tabs_search`, `home.mjs`) and docs. Documented the new options: README gained a Preferences Reference link + feature list (Library page, Home/new-tab, Workspaces, QuickTabs Search); `preferences.md` gained a **QuickTabs — Search Selection** section, the Library entry-point rundown, and `userchrome.home.debug`. Fixes broken README doc links (files live in `.documentation/`, not the root).

- **2026-10-19 19:20** [QuickTabs] **Task 5 — Search selected text in a Quick Tab.** New `JS/quick_tabs_search.uc.js`: with text selected, open a Quick Tab at the **default search engine's** results via a right-click item ("Search in Quick Tab …", shown only with a selection) or the **`Ctrl+Alt+S`** hotkey. Prefs `userchrome.quicktabs.search.{enabled,key,modifiers,menu}` with live rebinding; falls back to a normal tab if the QuickTabs mod is absent. (`Ctrl+Shift+S` from the roadmap is Firefox's Screenshot in FF157, hence `Ctrl+Alt+S`.)

- **2026-10-19 18:52** [Library] **Eliminated the legacy organizer entirely** (v1.2.0). Every entry point now lands on the Library page: `Tools:Downloads` (Ctrl+Shift+J) and the app-menu **Downloads** item map to the Downloads view; a **catch-all patch of `PlacesCommandHook.showPlacesOrganizer`** redirects anything else that would open `places.xhtml`, with `DownloadsPanel.showDownloadsHistory` patched to hide the popup and open the page. So the hamburger menu, the downloads popup footer ("Show all downloads"), bookmark-folder "Open in Library", and private-window downloads all stay in-page.

- **2026-10-17 13:26** [Library] Redirect now also intercepts the **`Browser:ShowAllHistory`** / **`Browser:ShowAllBookmarks`** `<command>`s (v1.1.0) — so the History/Bookmarks "Show All …" menu items **and** `Ctrl+Shift+H` / `Ctrl+Shift+O` open the Library page (on the History/Bookmarks view) instead of the Places organizer popup. Opens/focuses a single Library tab and switches its view via `#hash`.

- **2026-10-17 11:52** [Library] Download removal now **cancels an in-progress download first** (`dl.cancel()` when not `succeeded`/`canceled`/`error`) so the file is released before `IOUtils.remove` deletes it — applies to both per-row Delete/Delete file and the bulk buttons.

- **2026-10-16 20:03** [Library] Added file deletion for downloads: a per-row **"Delete file"** button (removes the download entry *and* the file on disk via `IOUtils.remove`) and a bulk **"Delete + files"** button (shown only in the Downloads view).

- **2026-10-16 19:37** [Library] Task 4: added a Library page (`resources/library/{library.html,library.mjs,library.css}` → `chrome://userchrome/content/library/library.html`) with **Bookmarks**, **History**, **Downloads** and **Tab Groups** views. Reads via Places SQL (`moz_bookmarks`/`moz_places`) and the `Downloads` API; deletes via `PlacesUtils.bookmarks.remove` / `PlacesUtils.history.remove` / `DownloadsList.remove`. **Batch management**: per-row checkbox, select-all (indeterminate), live "N selected", bulk delete per view, clear, plus per-row Open/Delete and a search filter. `JS/libraryRedirect.uc.js` repoints the toolbar Library button + app-menu entry to the page (pref `higgs.library.page.enabled`). Docs + plan updated; tests 27/27.

- **2026-10-15 10:27** [Workspaces] Task 3: added `JS/workspaces.uc.js` — Zen-style workspaces on **native Firefox tab groups** with a catch-all **Session** workspace for ungrouped tabs. `switchTo(id)` shows the target workspace's tabs and hides the rest (pinned tabs stay everywhere); the active workspace is persisted in `higgs.workspaces.active` and restored on `sessionstore-windows-restored`; new tabs join the active group workspace. Hotkeys `Ctrl+Alt+1…9` / `Ctrl+Alt+0`; exposes `window.HiggsWorkspaces`. Home page gained a **Workspaces** view (per-workspace grids, Switch button, active indicator). Docs + plan updated; tests 27/27.

- **2026-10-14 18:52** [Home / New Tab] Fixed the new-tab redirect (v1.2.0). Root cause: Firefox preloads `about:newtab` in a detached browser (`browser.newtab.preload = true`) and swaps it into a new tab **without** a fresh `onLocationChange`, so the progress listener never fired — `about:home` worked but `about:newtab` didn't. Added a `TabOpen` hook (deferred) that redirects the tab's browser, and disabled `browser.newtab.preload` so the normal navigation path also fires.

- **2026-10-14 18:25** [Home / New Tab] Hardened `JS/homeRedirect.uc.js` (v1.1.0): defer the navigation out of `onLocationChange` (synchronous `loadURI` there is unreliable), guard by `gBrowser.getTabForBrowser`, also redirect `about:home`, and add `higgs.home.debug` logging.
